<Case title="토큰 만료 시점에 동시에 발생하는 401">
  <Step label="문제">토큰이 만료되는 순간 이미지 생성·편집 요청이 여러 개 나가면 한꺼번에 401을 받았습니다. 그러면 갱신 요청이 중복되거나, 옛 토큰으로 다시 요청하거나, 실패한 요청이 그대로 유실됐습니다. 내부망 인증 서버와 브라우저 호출이 맞물려 CORS·쿠키 처리도 프론트에 몰려 있었습니다.</Step>
  <Step label="해결">refresh token 재발급은 백엔드로 옮겨 인증 흐름을 하나로 만들었습니다. 프론트에서는 공통 인터셉터가 401을 모아 갱신을 한 번만 실행하고, 기다리던 요청은 새 토큰으로 다시 보냅니다. 갱신이 실패하면 대기 요청을 비우고 로그인 만료 상태로 전환합니다.</Step>
  <Step label="결과" result>동시 요청 상황에서도 인증 실패 복구가 일관되게 동작, 서비스와 ADMIN에 같은 구조 적용</Step>
</Case>

```ts
let refreshing: Promise<void> | null = null;

async function onUnauthorized(request: Request) {
  // 이미 갱신 중이면 그 갱신을 함께 기다린다. 갱신 요청은 한 번만 나간다.
  refreshing ??= refreshToken().finally(() => {
    refreshing = null;
  });

  try {
    await refreshing;
  } catch {
    return expireSession(); // 갱신 실패: 대기 요청을 버리고 로그인 만료로 전환
  }
  return retry(request); // 새 토큰으로 다시 보낸다
}
```

<Note>실제 코드가 아니라 구조만 단순화한 예시입니다.</Note>
