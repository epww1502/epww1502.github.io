<Case title="AI 채팅 스트리밍 렌더링 최적화">
  <Step label="문제">답변이 스트리밍되는 동안 토큰이 올 때마다 store와 채팅 화면 전체가 다시 그려졌고, 다른 대화가 스트리밍 중일 때도 보고 있는 화면이 다시 그려졌습니다.</Step>
  <Step label="원인">이미 있던 throttle은 대기 값이 할당되지 않아 실제로는 동작하지 않았고, 대화 목록 구독이 채팅 화면 전체에 걸려 있었습니다.</Step>
  <Step label="해결">스트리밍 중에는 store 동기화를 건너뛰고, 메시지 컴포넌트 비교 함수로 마지막 메시지만 다시 그리게 했습니다. 대화 목록 구독은 사이드바로 옮겼습니다. 채팅 화면은 탭 밖 별도 스택으로 올리고 `freezeOnBlur`를 적용해, 보이지 않을 때는 상태를 유지한 채 렌더링만 멈추게 했습니다.</Step>
</Case>

```tsx
// 내용이 바뀐 메시지만 다시 그린다. 스트리밍 중에는 마지막 메시지만 해당된다.
const Message = memo(MessageView, (prev, next) =>
  prev.message.id === next.message.id && prev.message.text === next.message.text,
);

// 채팅은 탭 밖 스택에 두고, 보이지 않는 동안에는 렌더링을 멈춘다.
<Stack screenOptions={{ headerShown: false, freezeOnBlur: true }} />;
```

<Note>실제 코드가 아니라 구조만 단순화한 예시입니다.</Note>

<Case title="소셜 로그인과 Android의 Apple 계정 연결 해제">
  <Step label="상황">Kakao·Google·Apple 로그인을 지원해야 했고, App Store는 탈퇴할 때 Apple 계정 연결까지 해제하도록 요구합니다. 그런데 Android에는 Apple 로그인 SDK가 없습니다.</Step>
  <Step label="구현">Kakao SDK와 Firebase Auth(Google·Apple)로 로그인을 구성하고, 탈퇴 시 각 IdP의 토큰·코드를 서버에 함께 넘겨 연결을 해제했습니다. Android에서 Apple 인증 창을 띄우면 App Links 없이는 리다이렉트를 기다리다 창이 닫혔고, 쿼리로는 id_token을 받을 수 없었습니다. 그래서 웹 페이지에서 Apple JS로 code와 id_token을 한 번에 받아 `glab://` 딥링크로 앱에 넘기는 브릿지를 만들었습니다.</Step>
  <Step label="결과" result>세 플랫폼 모두 같은 로그인·탈퇴 흐름으로 스토어 심사 기준 충족</Step>
</Case>
